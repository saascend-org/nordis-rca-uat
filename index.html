    Test as the real person, not as an admin

    Admins see fields and buttons that ordinary users don't. Almost every defect found so far showed up only when testing as a sales rep.

    Add products with Browse Catalog

    Use the Browse Catalog action on the quote to add products. It runs Revenue Cloud pricing, so margins and approvals come out right. Don’t use any other way of adding lines.

    Reprice before you generate a proposal

    After configuring a bundle, reprice once before clicking Create Proposal. See DG-5 for why.

    Content now, formatting later

    For the proposal, judge whether the right things appear with the right numbers. Styling is still being refined. Put layout preferences in your notes, but don't reject a test for them alone.

    How to record a result

    1. Follow the steps and compare what you see with Expected.
    2. Choose Accept if it behaves as described, or Reject if it doesn't.
    3. Enter the quote, order or contract number you used. With that and your login, we can trace the problem without asking you to reproduce it.
    4. Add a note. For a rejection, say what happened and copy any error message word for word. For an acceptance, anything you'd like changed is still useful.

    Enter your name at the top of the page first, so your results are credited to you. Results save automatically to a shared sheet, and everyone's verdicts appear under each test, so two people can run the same test. Tests marked Key test are the ones most likely to expose a real problem, so run them first.

    Things that look odd but are known

    Submit and Recall always show on quotes

    Both buttons appear whatever the quote’s status. Hiding them by status is still to do. A second submission is still blocked with a message (AP-9).

    Several emails per approval

    Submitters are emailed at submission, decision and outcome. Tell us if that's too many.

    Contract outcome emails omit comments

    The email back to the submitter is the standard Salesforce one. Approver comments are always on the contract in Approval Comments.

    Approved records lock

    Approval locks the record to protect the agreed pricing and terms. Admins can unlock it if needed.

    Leave Tax and Shipping blank

    Postage is priced on the lines. Typing a value into the quote’s Tax or Shipping & Handling field counts it twice in the grand total.

    Proposal limit in the sandbox

    The sandbox allows 50 document generations an hour across all users. Anything over that comes back as Blocked. Wait a while and try again.

    No automatic pull-back on contracts

    Ticking a risk box after a contract is approved doesn't send it back for approval. The record lock is what prevents that change. Quotes do pull back (AP-8).
